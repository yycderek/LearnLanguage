# LearnLanguage 架构草案

## 核心原则

不同语言共享学习流程，但语言差异不能简化为替换语料。系统将通用能力、语言规则和课程内容分成三个独立层次。

## 三层架构

### 通用学习引擎

负责能力目标、课前诊断、最小知识预教、支架输入、理解验证、渐进输出、掌握证据投影、版本化间隔复习和迁移测试。AI 请求是引擎声明的可选 Effect，不进入确定性状态机决策。

## 跨客户端应用服务

`@learn-language/application` 是客户端界面与领域能力之间的用例边界。学习会话、课程编排、草稿修订、Language Pack 生命周期、课程安装和学习档案恢复分别由应用服务接收显式命令，并通过 Repository 合约持久化。服务不读取 DOM、React 状态、浏览器存储、系统时间或随机数，也不显示确认框；这些输入和用户决定由客户端提供。

Web 的 IndexedDB、未来移动端和桌面端的 SQLite 都只是 Repository 适配器。React 页面可以组合服务并显示结果，但不能重新实现课节重排、修订编号、档案合并、内置内容保护、引用保护或安装兼容性等业务规则。涉及课程版本与学习记录的原子更新仍由客户端 Repository 的事务实现，并接受同一兼容性策略。

### 语言包

当前负责书写系统、文本规范化、分词、语法知识类型、书写方向、难度框架和能力声明。`@learn-language/language-runtime` 在 Web、移动端或桌面端界面之外解析 Language Pack，并只暴露实际可执行的能力；内置日语和粤语适配器与通用回退运行时使用同一接口。练习声明所需语言能力；能力不足时必须显式选择学习者自评、参考答案或跳过且不计证据。发音、录音、TTS/STT 与语音评分暂不进入当前实现范围，当前数据协议也不保留这些字段；未来如需恢复，应通过新的协议版本和迁移规则引入。

Language Pack 是独立、可迁移的标准 JSON 定义，不与课程内容或学习记录捆绑。内置定义随应用版本维护，不能被设备文件覆盖；自定义定义保存在设备 Repository 中，可以导入和导出。删除前必须检查 Studio 当前编辑内容、草稿集合和 Learn 已安装课程的稳定 `languageId` 引用。替换同 ID 定义属于运行时行为变更，存在引用时必须由用户明确确认。

课程进入发布、预览或 Learn 前必须生成语言运行时兼容性报告。报告同时比较目标语言 ID、课程固定的适配器 ID/版本、Language Pack 声明、注册表中实际可执行的适配器以及练习所需能力。阻塞问题停止操作；能力不足但存在显式 `capabilityFallback` 时标记为降级并允许继续。缺失 Language Pack 或适配器不能被客户端当作原生能力。

### 课程包

负责 Can-do 目标、场景、知识点、语料、媒体资源、练习、角色任务和评分标准。发布版本包含来源、许可证、固定语言适配器版本和可复验的内容哈希；复习任务由引擎根据掌握证据生成，不由课程内容直接决定。

内置课程同样是标准 Course Pack 数据，不在学习引擎或客户端播放器中加入语种条件分支。当前日语和粤语入门课程分别提供三个递进课节；新增语种可先使用通用可编辑脚手架，再通过 Studio 或数据文件补充完整课程。语言适配器只处理可复用的语言能力，课程可以在必要时保存某一语种特有的知识类型、读音字段和任务设计。

练习交互采用两段式边界：`@learn-language/application` 定义与客户端无关的选择、排序和文本响应，负责初始化、序列化与确定性答案判定；Web、移动端和桌面端各自注册视觉渲染器，只采集响应。学习引擎始终只接收序列化答案和标准提交事件，不依赖 React、DOM、拖拽组件或某种设备交互。

## 两种用户可见语言维度

- 目标语言是课程教授的语言，由 `CourseManifest.languageId` 指定。
- 应用语言同时控制导航、编辑控件、解释、翻译、任务提示、日期格式和 AI 反馈，属于设备偏好；当前正式支持中文和英文。

课程本地化字段仍保留多个语言版本，并按精确 locale、同语种变体、另一正式应用语言、native/任意首值的顺序确定性回退。缺失翻译不会阻塞纯本地学习；Studio 的统一语言选择器也决定当前维护哪个本地化版本。

## 用户内容

用户创建的内容默认保存为私人草稿，经过格式验证和课程预览后才能使用。Studio 可以在不编辑 JSON 的情况下编排多个课节，并为每个课节独立维护目标和线性学习步骤；排序或删除步骤时会重新生成入口和后继引用。未来可选择分享或发布，但不能直接修改官方课程数据。

草稿管理属于 Studio 创作空间，不进入 Learn 课程库。设备端以草稿 ID 聚合有限数量的修订快照；恢复旧修订只改变当前编辑器和后续修订基线，不修改已发布课程或学习进度。草稿文件继续使用标准 Course Pack v2 JSON，导入时必须校验结构与领域引用，并拒绝把已发布或已归档内容当作可编辑草稿。发布课程若需修改，应显式创建带来源关系的派生草稿。草稿删除与学习档案恢复互不影响。

## 设备本地课程库

Learn 的课程目录与学习引擎分离：目录负责发现、来源和版本状态，安装存储负责设备上的 Course Pack，学习引擎只接收用户已经安装的具体版本。内置课程也以包含许可证和内容哈希的发布包安装，不因随应用分发而绕过完整性校验。

卸载只删除设备上的课程包，课程学习记录继续按稳定的课程 ID 保存。版本更新必须保持课程 ID、目标语言和 Schema，并保留现有学习记录引用的课节、步骤和知识点；兼容更新会同时替换课程包并重标学习记录版本，不兼容更新必须停止并等待显式迁移方案。

课程文件是发布 Course Pack 的 UTF-8 JSON 表示，不是新的协议格式。Learn 可以从本地文件导入，但必须限制文件大小，并重新执行 Schema、领域引用、发布状态和内容哈希校验；同课程 ID 的较新文件进入版本兼容流程。导出仅序列化已发布课程，不包含学习记录、设备偏好、AI 密钥或账户信息。

无账户模式通过用户主动下载的学习档案提供设备迁移能力，不把浏览器存储伪装成跨设备持久化。档案仅包含可重建的学习投影：已完成课节、掌握度、复习任务和复习结果；学习答案、活动会话、待处理 Effect、课程内容、草稿、偏好和 AI 配置均被排除。恢复按稳定课程 ID 合并，只有更新时间更晚的备份记录可以替换本地记录，多个变更在一个 IndexedDB 事务中提交。此机制不替代可选同步服务。

## 可选同步服务

本地 Repository 始终是客户端的可用事实来源；同步是可替换的外部适配器，不进入学习引擎。客户端先请求 `/.well-known/learn-language-sync`，确认协议版本、认证方式、资源范围、批量上限和冲突策略，再决定是否启用。

同步协议使用档案 ID 而不是强制账户 ID，因此可以支持匿名自托管档案或带 Bearer 身份的托管服务。变更按游标增量拉取，提交使用 mutation ID 实现幂等，并通过 base version 拒绝陈旧写入。冲突必须交给客户端合并或让用户选择，服务端不采用静默最后写入覆盖。

`@learn-language/sync` 的参考实现只使用内存和标准 Web Request/Response，用于验证协议和演示适配器；生产后端必须替换持久化、认证、限流和备份实现。

## 首个通用化验证

1. 使用同一学习引擎加载两种语言包。
2. 两个语种的学习进度相互独立。
3. 用户可以创建、预览并运行一节私人课程。
4. 核心引擎不包含针对具体语言的条件分支。
5. AI 服务不可用时，确定性课程仍可运行。
