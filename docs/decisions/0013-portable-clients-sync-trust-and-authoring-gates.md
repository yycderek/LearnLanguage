# ADR 0013：可移植客户端、可选同步、来源信任与创作门禁

## 状态

已接受，2026-08-13。

## 背景

R12 与 R13 已经把核心用例和语言运行时从 Web 界面分离，但仍需要用第二种存储和非 Web 执行环境证明边界真实可替换。同时，设备迁移不能只依赖手工文件；社区课程也不能因为结构合法就自动被视为官方可信内容。面向不懂代码的课程作者，发布失败还需要在提交前转化成可理解的检查清单。

## 决策

- 应用 Repository 同时提供内存、IndexedDB 和 SQLite 适配器，并接受共享合约测试。
- Headless SQLite 客户端作为跨客户端架构门禁，必须在没有 React、DOM 和浏览器存储的环境中完成关键用例。
- 同步保持账户可选和本地优先；客户端先发现能力，再推送本地变更并按游标拉取远端变更。
- 同步冲突采用服务端拒绝陈旧写入，必须由用户明确选择重新基于远端版本提交本机修改，或采用服务端版本。
- 同步访问令牌属于会话秘密，不进入设备长期存储、学习档案或课程包。
- 课程结构完整性、运行时兼容性和内容来源信任是三个独立门禁。官方身份只对受信作者成立，社区和本地内容必须显示作者、许可证和来源并在安装前确认。
- Studio 用模板、课节复制和发布检查清单降低无代码创作门槛，但模板生成的内容仍是普通 Course Pack，不引入第二套课程模型。

## 结果

未来移动端和桌面端可以直接复用应用服务、语言运行时、同步协议和信任策略，只需要替换界面、系统集成和 Repository 适配器。没有账户或同步服务时，本地课程、进度、草稿和档案仍然完整可用；开启同步时，冲突不会静默覆盖。课程作者可以在可视化界面中完成发布前检查，而高级用户仍可使用同一 JSON 协议。
