# ADR 0012：跨客户端应用服务与语言运行时门禁

## 状态

已接受，2026-08-11。

## 背景

学习状态机已经与 Web 界面解耦，但草稿修订、课程安装和 Language Pack 生命周期仍由 React 组件直接编排。与此同时，发布课程虽然固定适配器版本，客户端却没有统一检查 Language Pack、注册适配器和练习能力，缺少语言包时甚至可能被界面视为原生支持。这两个问题会阻碍移动端和桌面端复用，也可能让同一课程在不同设备产生不同运行行为。

## 决策

- 在 `@learn-language/application` 中定义课程创作、草稿、Language Pack、已安装课程和学习档案的 Repository 合约、应用服务及领域错误。
- 时间、随机 ID、用户确认和本地化提示由客户端提供；应用服务只执行确定性用例规则。
- Web IndexedDB 作为第一套 Repository 适配器，未来客户端可以使用 SQLite 而不改变服务接口。
- `@learn-language/language-runtime` 统一评估课程与 Language Pack，输出兼容、降级或阻塞报告。
- 发布、预览、安装、更新、导入、打开课程和应用恢复都使用相同评估结果。
- 课程固定非通用适配器时，Language Pack 声明和注册表中的实际版本必须完全匹配。
- 缺少练习能力时，只有课程显式声明降级方式才允许继续；缺少 Language Pack 一律阻塞。

## 结果

核心用例不再依赖 React 或 IndexedDB，可以使用内存 Repository 做合约测试并由其他客户端复用。课程安装不再只验证文件哈希，还验证设备是否具备可执行的语言运行时。显式降级仍允许通用语言工具覆盖没有专用适配器的语种，但不会静默提升掌握证据或把缺失能力伪装成原生支持。
